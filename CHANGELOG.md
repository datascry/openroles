## [Unreleased]

### Added

- Project scaffold: bun workspaces, TypeScript strict mode, Biome lint + format, Bun test runner with coverage.
- Pre-commit hooks via lefthook: Biome check, type check, commitlint.
- CI workflow scaffold for PRs (lint, typecheck, test, dependency review, CodeQL).
- ADR template plus ten initial Architecture Decision Records covering runtime, data layer, harvest model, frontend, deployment shape, licensing, framework choices, TDD discipline, subscription model, and the phase plan.
- Spec skeleton: data schema, scraper contract, filter UI, RSS feeds.
- MIT license for code; CC BY-SA 4.0 for harvested dataset.
- Shared zod schemas for ATSId, Level, WorkplaceType, Tenant, Job, ScrapeInput/Output, and Manifest, with derived `level_rank` and stable SHA-256 `Job.id` hashing.
- HTTP client with project-identifying User-Agent, exponential backoff with jitter, `Retry-After` honoring, per-host robots.txt cache (24h TTL, fail-closed on 5xx/network), 30s timeout, no cookies.
- Six ATS scrapers — Greenhouse, Lever, Ashby, BambooHR, Workday (paginated), iCIMS (sitemap + JSON-LD walk) — each with three fixture-replay tests, a determinism property test, retry coverage, and a robots.txt block test.
- Scrape orchestrator with per-ATS p-limit concurrency, dispatch by ATS id, and a CLI `scrape` subcommand reading a `ScrapeInput` JSON file.
- Level and recruiter classifiers as pure functions over title/department text, with property tests asserting determinism and closed-set output.
- SQLite build pipeline (`bun:sqlite`): per-spec schema (jobs/tenants/crawls), seven covering indexes, and an FTS5 virtual table over title/company/description with porter+unicode61 tokenization; `page_size = 1024` matches the `sql.js-httpvfs` request chunk size, and `VACUUM` plus FTS `optimize` run as the final build step.
- CLI `build-db` subcommand reads a directory of scrape outputs, validates them through the zod schema boundary, applies classifiers, writes `jobs.{sha}.sqlite`, and emits `manifest.json` alongside.
- Filter UI state machinery: URL ↔ FilterState round-trip with property tests, parameterized SQL builder over the FTS5 + jobs schema, and localStorage helpers for saved / applied / ignored lists.
- RSS feed generator with XML/CDATA escaping, item-cap of 100, 90-day freshness window, and stable sort order; static Astro endpoints for `/feed.xml`, `/feed/{ats}.xml`, and `/feed/level/{level}.xml`.
- Static per-tenant pages at `/tenant/{ats}/{slug}` rendered from the SQLite database at build time.
- Index page with the `FilterTable` Svelte island hydrated `client:idle`, mobile-first CSS layered on Open Props tokens, and a manifest-aware empty state when the database has not been built yet.
- Site build runs under Bun (`bun --bun astro build`) so endpoints and pages can use `bun:sqlite` directly at static-route generation time.
- Common Crawl harvester: per-ATS regex patterns + deny-list (`scraper/src/harvest/patterns.ts`), CDX-index URL builder + JSON Lines parser, deterministic slug extractor that dedupes across snapshots, RFC-1123-style slug guard, and a liveness probe that maps HTTP results onto the `Tenant.status` enum (live / dead / transient_failure).
- CLI `harvest` subcommand reads one or more CC-MAIN snapshots, extracts tenant slugs through the per-ATS regex, optionally probes each candidate, and writes `data/tenants/{ats}.json` atomically via tmp + rename.
- Drift detector compares the current build's manifest against the previous build, emitting categorized findings (info / warn / error) for total-row drops, per-ATS drops, ATS counts that zeroed out, schema-version changes, and tenants_live drops.
- Dead-tenant tracker walks a sequence of historical tenant snapshots and surfaces tenants that were dead in every snapshot of the trailing window, with deterministic (ats, slug) ordering.
- Run-report generator renders a Markdown summary including build identity, totals, per-ATS counts, drift findings, and dead-tenant alerts; locale-stable number and duration formatting.
- CLI `report` subcommand reads `data/manifest.json` plus per-ATS scrape outputs, optionally compares against `--previous-manifest` for drift, optionally walks `--tenants-history` for dead-tenant alerts, and exits non-zero when drift severity reaches `--fail-on` so CI fails loudly on regressions.
- Mutation testing is deferred until StrykerJS gains first-class Bun support; the rationale is recorded in [ADR-0010](docs/adr/0010-phase-plan.md).
- Daily refresh GitHub Action (`.github/workflows/daily-refresh.yml`): builds per-ATS scrape inputs from the checked-in tenant lists, runs each scraper, builds `jobs.{sha}.sqlite` and `manifest.json`, runs the drift report, builds the static site, and deploys to GitHub Pages via `actions/upload-pages-artifact@v3` + `actions/deploy-pages@v4`. Scheduled at 05:17 UTC daily; manual dispatch supports a `deploy: false` dry-run.
- Weekly harvest GitHub Action (`.github/workflows/weekly-harvest.yml`): runs the Common Crawl harvester for each ATS, summarizes tenant counts, and commits `data/tenants/{ats}.json` back to `main` with `[skip ci]`. Scheduled at 02:43 UTC each Monday; manual dispatch accepts `--snapshots` and `probe` overrides.
- Tenant lists (`data/tenants/{ats}.json`) are now treated as checked-in inputs rather than build outputs, refreshed by the weekly harvest workflow.
- Bundle-size budgets (`site/.size-limit.json`) defended in CI: FilterTable island ≤ 25 KB gzip, Svelte runtime ≤ 20 KB gzip, all client JS ≤ 50 KB gzip, global CSS ≤ 15 KB gzip, index HTML ≤ 30 KB gzip (covers Astro's auto-inlined CSS). The `size-limit` PR job is now enabled.
- Playwright e2e + a11y harness (`site/playwright.config.ts`, `site/tests/e2e/smoke.spec.ts`): page-chrome smoke, axe WCAG 2 AA critical/serious assertion, FilterTable hydration verified by clicking an ATS chip and asserting the URL updates (proves event handlers wired, not just SSR shell rendered), and `/feed.xml` dual-state contract. Runs against `bun --bun astro preview` on chromium + Pixel 7 viewport. The `e2e` PR job is now enabled.
- `parseNumPages` test coverage for the CDX `showNumPages` JSON-form fallback in `scraper/src/harvest/cdx.ts`, lifting the file above the 95 % per-file threshold.
- Root package scripts (`bun run scrape`, `build`, `e2e`, etc.) corrected to use the fully-qualified workspace names (`@openroles/scraper`, `@openroles/site`); the unqualified `--filter site` form silently matched no packages and printed `error: No packages matched the filter`.
- Adversarial review remediation (post-Phase-7 audit gate per [ADR-0010](docs/adr/0010-phase-plan.md)): `pr.yml` test job now invokes `bun run test` so the Playwright spec ignore-pattern from `package.json` actually applies (otherwise bare `bun test --coverage` discovers `*.spec.ts` and fails); first-run safety in `daily-refresh.yml` (warning instead of hard-exit when all tenant lists are empty); shape-validation of the `weekly-harvest` `snapshots` dispatch input to close an argument-laundering vector; `${{ github.workflow }}` self-scoped concurrency groups; seeded `data/tenants/*.json` placeholders so the first scheduled run produces a valid empty manifest rather than crashing.
- **Phase 8 — client-side query runtime.** The Svelte FilterTable now boots a sql.js-httpvfs Web Worker on `client:idle`, fetches `data/manifest.json`, and serves SQLite b-tree pages via HTTP `Range` requests over the deployed `data/jobs.{sha}.sqlite`. Filter state changes (search, ATS chip, level chip, workplace, sort, since-window, recruiter toggle) flow through `buildFilterQuery` into the worker; results render as mobile-first job cards with loading / empty / error states. The bundle stays under budget (FilterTable island 18.4 KB gzip / 25 KB limit; all client JS 34.7 KB gzip / 50 KB limit) by code-splitting `sql.js-httpvfs` behind a dynamic import and serving the Worker JS + WASM as static assets from `/sqlite-vfs/` rather than bundling them.
- `site/src/lib/client-db.ts` — manifest fetch with shape validation (no zod in the client bundle), `createDbWorker` bootstrap, and a `query(sql, params)` adapter that passes params as a single array to bind correctly into sql.js's positional placeholders.
- `site/scripts/build-fixture-db.ts` — deterministic 4-job SQLite + manifest used by Playwright `globalSetup` so the runtime e2e exercises real query results, not just the SSR shell.
- `site/scripts/copy-sqlite-vfs.ts` — copies `sqlite.worker.js` and `sql-wasm.wasm` from `node_modules` into `site/public/sqlite-vfs/` at every `bun run build` / `bun run dev`. The copies are gitignored.
- New e2e specs: "renders job results from the fixture database" (asserts 4 rows render) and "clicking an ATS chip narrows the result set" (clicks a chip, asserts the result count drops to the expected ATS-only subset). Together with the existing hydration test these prove the runtime is wired end-to-end on chromium + Pixel 7.
- Phase 8 audit-gate remediation per [ADR-0010](docs/adr/0010-phase-plan.md): hoisted `HttpUrl` to `shared/src/schema/url.ts` and tightened `Job.url` + `ScrapeInput.contactUrl` to reject non-http(s) schemes, closing a `<a href={row.url}>` XSS vector that mirrored the Phase 7 `Tenant.homepage_url` fix; split client-db into `manifest-runtime.ts` (testable) + `client-db.ts` (Web Worker, exercised by Playwright) with full unit coverage of `parseManifest` / `fetchManifest` / `buildRuntimeUrls`; added a defense-in-depth cross-check that `manifest.db_filename` matches `manifest.short_sha`; decoupled per-query failures from terminal load failures so transient errors don't latch the panel; made Playwright `globalSetup` build the site itself if `dist/` is missing; updated `specs/filter-ui.md` to match what shipped vs what's deferred.
- Filter UI now ships the deferred surfaces from `specs/filter-ui.md`: pagination controls (prev/next + "page X of Y"), since-window dropdown (any time / 24h / 7d / 30d), min-comp numeric input, and save/apply/ignore lists wired to the existing `lib/storage.ts` localStorage helpers. Save and ignore expose `aria-pressed`; ignored rows hide by default with a "Hide ignored (N)" toggle to surface them; clicking through to a job auto-marks it applied and fades the row to 70 % opacity. Fixture DB grew from 4 to 56 rows so the pager has something to do.
- Phase 8 audit minor-finding cleanup: 50 ms debounce on `runQuery` to coalesce rapid chip clicks (audit M4); `JobRow` is now a `Pick<Job, …>` so the row type stays in lockstep with the schema; `formatPostedAt` round-trips through `Date` to survive ISO format drift; `console.debug` gated behind `import.meta.env.DEV`; ARIA double-announce fixed by moving `aria-busy` to the status line and dropping the redundant live region from `.data-pending`; dead `runPlan` export removed.
- Lighthouse audit runs as a Playwright project (`tests/e2e/lighthouse.spec.ts`) using `playwright-lighthouse` rather than `@lhci/cli`. Thresholds: performance ≥ 60 (conservative — the sql.js WASM pulls ~650 KB on first paint), accessibility ≥ 95, best-practices ≥ 90, SEO ≥ 90. The audit shares the existing Playwright `webServer` + `globalSetup` so the fixture DB is loaded; CI runs it as part of the existing `e2e` job rather than a separate workflow step. `pr.yml`'s previously-gated `lighthouse` job is removed.
- Harvest tenant-discovery overhaul backed by an empirical sweep of CC-MAIN-2026-12: (1) the iCIMS `cdxQuery` `careers-*.icims.com/*` returned 0 records — CDX prefix-match semantics in SURT form do not honor wildcards inside a host segment. Switched to `*.icims.com/*` and rewrote the slug to be the full subdomain label rather than the suffix of `careers-{slug}`. Recovers ~2,475 distinct iCIMS tenants per snapshot from 0; only ~57 % of real iCIMS career sites use the `careers-` prefix anyway. The probe and scraper compose URLs as `https://{slug}.icims.com/sitemap.xml`. (2) Greenhouse `embed/job_app` arm dropped — `Disallow: /embed/` in greenhouse's robots.txt means CCBot never crawls those paths, and the alternation is empirically dead. (3) Default snapshot window widened from 4 to 8 so harvests survive per-ATS robots changes (e.g. Lever's recent CCBot block via Cloudflare; pre-block snapshots still hold ~2,500 valid Lever slugs that the wider window picks up). (4) Subdomain deny list extended to include `admin`, `login`, `auth` so iCIMS infrastructure subdomains are filtered.
