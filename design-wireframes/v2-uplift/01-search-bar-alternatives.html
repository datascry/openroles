Search bar

The current bar is a single text input that teaches a 5-prefix DSL through placeholder copy. It works for power users; it's invisible to everyone else. Each alternative below makes the structured search legible without losing keyboard speed.

Alt 1 — Command bar with token suggestions

Type → suggest → tokenise

A single input that auto-suggests the right prefix as the user types. Accepting a suggestion (Enter / Tab) converts the term into a solid black token chip inside the field. Empty the input → see "recent searches".

Best for: power users + first-timers, single hand on keyboardCost: needs autocomplete index in JS

Alt 2 — Dual-mode tabbed search

Free text · or · structured fields

Two tabs sit above the search surface: FREE TEXT (today's behaviour, exposed plainly) and STRUCTURED (named inputs for title, company, location). Recent searches appear below either mode and round-trip both directions.

Best for: users who don't trust DSLsCost: two layouts to maintain, mode-switching cost
Recent title:engineer "staff product designer" company:stripe
Saved searches Senior IC · remote · last 7d EU staff eng · ≥ 130k + Save current

Both modes write to the same FilterState — switching tabs preserves the query (a structured "company: stripe" shows up as company:stripe in free-text mode and vice versa).

Adds first-class "saved searches" surface — the closest the no-account product can get to "job alerts".

Heaviest of the three. Probably overkill unless analytics show the DSL is failing for non-power users.

Alt 3 — Persistent search + quick-prefix shortcuts

One bar, four pre-typed prefixes

Keep the existing single search input but add a row of pre-typed prefix shortcuts directly underneath. Tapping one inserts title: (or company/location/skill) at the cursor and focuses the input. The DSL becomes discoverable without changing the data path.

Best for: minimum-disruption uplift, ships fastestCost: still requires DSL literacy after first tap
