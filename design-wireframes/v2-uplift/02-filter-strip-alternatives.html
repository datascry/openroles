openroles · uplift wireframes · FILTER STRIP — 3 alternatives

Filter strip

Today's + ATS, + Level, + Workplace, + Posted, + Min comp, + No recruiters, + Verified only, + Saved, + Applied, + Ignored, plus Sort, plus Reset = 12 controls in one row. The total selectable surface area is 54 enumerable values (24 ATS + 10 levels + 3 workplace + 4 since + 8 sort + 5 toggles) plus a free-form min comp input. Each alternative below treats that scale as a first-class problem.

Alt 1 — Persistent sidebar (desktop) + sheet (mobile)

Filters live in a left rail

Desktop puts every filter group in a 280-px sidebar. Each group has a header with active count, a search field where lists are long (24 ATS, 10 levels), and progressive disclosure ("Show all 24"). Mobile collapses to a sheet behind one button.

Best for: heavy multi-filter sessions, comparison shoppingCost: 280 px of horizontal real-estate, biggest layout change

Alt 2 — Active-only chips + one FILTERS button

The bar is empty until you choose

Default state: a single solid FILTERS button. Activating filters renders them inline as removable chips with explicit key:value labels. The filters button opens a two-pane panel — left rail picks the dimension, right pane shows that dimension's options.

Best for: mobile-first parity, calmest defaultCost: options are one click away (slightly more friction)

Active state is visible instead of buried: chips read as `key:value`, mirroring the search DSL for consistency.

The panel groups ATS into "major" + "all others" to soften the 24-option list — same pattern can apply to levels (entry/mid/senior split out) if needed.

Live result count in the panel footer (`14 results match · live preview`) lets the user judge filter impact before committing.

Same panel works on mobile by stacking the two columns vertically.

Alt 3 — Categorised tab groups

Five named slots, each with current value

Treat the filter row as five header cells, each named after a dimension and showing its current value (or "Any"). Clicking a cell expands a tray below the row with that dimension's options. Always one tray open at most.

Best for: always-visible state, "facet" feel of an editorial broadsheetCost: harder to scan many active filters at once

The current selection becomes the cell's value text, so you never have to open a tray just to remember what you set.

"Personal" filters (Saved / Applied / Ignored) live outside this row in a separate "MY VIEW" toggle bar — they're a different mental model and were the most-confusing item in the existing strip.

Inline counts on each option (`senior 22`, `staff 5`) help users predict result count before clicking — major ergonomic win for sites that aggregate.

Could collapse to a single "FILTERS ▾" cell on phones if five cells get too narrow.
