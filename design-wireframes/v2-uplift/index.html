Audit findings

SeverityAreaFinding
CRIT Role detail RoleDetail.svelte styling references --color-muted, --color-surface-2, --color-border, --font-size-3 — none of which exist in the current Brutalist Press tokens. The page is silently rendering with browser defaults for those properties. Fix at the same time as the redesign.
MOD Filter strip 12 controls in one wrapping row with a single visual treatment (dashed + button) for two interaction models — popover-openers vs boolean toggles. Cognitively expensive to scan; gets worse as filters scale.
MOD Filter strip No way to know how many active filters exist or what they're set to without reading every chip. No "active count" affordance.
MOD Search bar DSL is taught only by the placeholder string, which is truncated on small viewports. New users won't discover title:, company:, etc. unless they happen to expand the <details>.
MOD Index page Lede h2 ("Find your next role.") repeats what the masthead already says and pushes the search input below the fold on phones.
MOD Personal state "Saved", "Applied", "Ignored" toggles imply server-side state but actually live in localStorage. No disclosure on either the index or the role page.
MOD Loading state First paint shows LOADING… as the only state. SQLite-over-HTTP can be multi-second on a cold cache. A deterministic skeleton (e.g. faint result rows) would set expectations better.
MIN Filter strip Sort: NEWEST FIRST mashes label and value into one all-caps run; hard to tell what's persistent vs current.
MIN Filter strip Border treatments inside the bar use three weights (1px solid, 1px dashed, 2px solid) for adjacent buttons. Lock to two states.
MIN Theming Theme toggle button has no visible label — aria-label only. Sighted keyboard users tabbing through see only an icon.
MIN Tokens --color-ink-3 at --text-0 / --text-00 sits at 5.46:1 against paper — passes WCAG AA but with no headroom. A locked Playwright contrast snapshot would protect it.

Recommended path forward

  1. Fix the role-detail token rot first. The page references CSS custom properties that don't exist in tokens.css. This is a one-day change and unblocks any of the three role-detail wireframes.
  2. Adopt the active-only chip strip with a FILTERS panel (alt 2 of surface 2). Cheapest of the three filter alternatives, removes the dashed-button ambiguity, and the panel layout lets you scale to ten more filters without a redesign.
  3. Adopt the prefix-shortcut search bar (alt 3 of surface 1). Smallest API change to the existing FilterTable; teaches the DSL without removing it. The token-suggesting command bar (alt 1) is the long-term winner but needs an autocomplete index.
  4. Adopt the triage card stack for role detail (alt 2 of surface 3). Sticky CTA, explicit "not stated" fields, and pivot filters keep users in the funnel and address the local-storage disclosure issue inline.
  5. Promote the live count, drop the lede h2. Replace "Find your next role." with the freshness/inventory signal the strap already carries (56 OPEN ROLES · UPDATED TODAY) and let the search input be the next line.
  6. Skeleton loading state. Replace LOADING… with five faint job-row outlines; matches the editorial aesthetic ("newspapers don't go blank, they print column rules") and hides the SQLite-over-HTTP latency.
